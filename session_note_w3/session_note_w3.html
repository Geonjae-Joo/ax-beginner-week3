03 · LANGCHAIN04/10
01 · BUILD — 기반 추상화

LangChain — LLM을 코드로

LLM 호출 코드를 어떻게 깔끔하고 교체 가능하게 만들 수 있을까? Claude · GPT를 오갈 때마다 함수를 새로 짤 수는 없다.

4가지 컴포넌트, | 연산자로 연결

  • ChatModelLLM 추상화. ChatAnthropic · ChatOpenAI 동일 호출. 모델 교체해도 코드 그대로.
  • Promptsystem + human 메시지 템플릿. {변수}로 입력 주입. 재사용 가능.
  • ParserAIMessage → str · JSON · Pydantic 객체. 후속 단계가 쓰기 쉬운 형태로.
  • LCELchain = prompt | llm | parser — 좌→우로 데이터가 흐름.
한계

LCEL은 A → B → C 선형만 가능. Tool 결과 보고 다시 LLM에 묻는 루프나, 입력에 따라 다른 경로 분기는 못 한다. → 다음: LangGraph

# 1. 모델 — 어떤 LLM도 동일한 방식
from langchain_anthropic import ChatAnthropic

llm = ChatAnthropic(
    model="claude-haiku-4-5-20251001",
    temperature=0,
)

# 2. 프롬프트 — 재사용 가능한 템플릿
from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages([
    ("system", "당신은 수학 전문가입니다."),
    ("human",  "{question}"),
])

# 3. 파서 — AIMessage → str
from langchain_core.output_parsers import StrOutputParser

parser = StrOutputParser()

# 4. LCEL — | 연산자로 체인 조립
chain = prompt | llm | parser

answer: str = chain.invoke({
    "question": "미분이란?"
})
04 · LANGGRAPH05/10
01 · BUILD — 흐름 오케스트레이션

LangGraph — 그래프로 흐름을

Tool 결과를 보고 다시 LLM에 넘기는 루프가 필요하다. 입력에 따라 다른 모드로 분기해야 한다. 체인은 못 한다.

지하철 노선도처럼 — 각 역(Node)에서 State에 따라 다음 방향 결정. 환승(루프)도 가능.

3가지 핵심만 기억하세요

01 · STATE — 공유 메모리

모든 노드가 공유하는 TypedDict. add_messages Reducer가 노드별 반환값을 자동 누적 (덮어쓰지 않음).

02 · NODE — 상태 변환 함수

State를 받아 State 일부를 반환하는 함수. def chat(state) -> dict. 그래프에 등록되어 엣지에 의해 호출됨.

03 · EDGE — 연결 규칙

일반: 항상 다음 노드로. 조건: 함수가 반환한 문자열로 분기. add_conditional_edges().

05 · TOOLS06/10
01 · BUILD — 에이전트의 행동

Tool Calling — LLM의 손과 발

LLM은 23 × 47도 못 푼다. 행렬식·미분은 더더욱. 어떻게 외부 함수를 호출하게 할 수 있을까?

지휘자(LLM)와 연주자(코드) — LLM은 "어떤 함수를 어떤 인자로 호출할지"만 결정, 실제 실행은 코드가 담당.

ReAct 루프 — Tool 호출의 표준 패턴

▸ THOUGHT"미분이니까 calculus 도구가 필요해"
↓
▸ ACTIONLLM이 tool_calls 생성 (메시지로 표현)
↓
▸ EXECUTEToolNode가 실제 함수 실행
↓
▸ OBSERVE결과를 ToolMessage로 LLM에 반환
↓
▸ LOOP/DONE더 필요? → 다시 Thought / 충분? → 최종 답
오늘 만들 Tool 3종

arithmetic — 사칙연산·거듭제곱 (ast 안전 eval) · calculus — 미분·적분 (sympy) · matrix — 행렬식·역행렬·행렬곱 (numpy)

# 1. @tool 데코레이터로 함수 등록
from langchain_core.tools import tool
import sympy as sp

@tool
def calculus(
    expression: str,
    variable: str = "x",
    operation: str = "diff",
) -> str:
    """미분·적분 계산. 'diff' | 'integrate'"""
    var = sp.Symbol(variable)
    expr = sp.sympify(expression)
    if operation == "diff":
        return str(sp.diff(expr, var))
    return str(sp.integrate(expr, var))

# 2. LLM에 Tool 바인딩 — 사용법을 인지시킨다
llm_with_tools = llm.bind_tools([
    arithmetic, calculus, matrix_calc
])

# 3. ToolNode — 자동 실행
from langgraph.prebuilt import ToolNode
tool_executor = ToolNode([
    arithmetic, calculus, matrix_calc
])

# LLM은 tool_calls만 생성
# ToolNode가 실제 함수 실행 → ToolMessage 반환

CODE EVALUATOR — 수치 정확도

"답이 맞는가?"

기댓값과 예측값을 직접 비교. 숫자는 ±0.01 오차 허용, 심볼릭 표현은 sympy로 동치 확인.

def code_eval(row):
    pred, exp = row["predicted"], row["expected"]
    # 1) 수치 비교 (3.14 vs 3.141)
    try:
        if abs(float(pred) - float(exp)) < 0.01:
            return {"score": 1}
    except: pass
    # 2) 심볼릭 동치 (x**2 == x*x)
    diff = sp.simplify(sp.sympify(pred) - sp.sympify(exp))
    return {"score": 1 if diff == 0 else 0}

LangServe — 한 줄로 REST API

에이전트는 동작하지만, 다른 앱 · 웹 클라이언트 · curl에서 호출하려면? FastAPI 라우터를 손으로 짤 수도 있지만, graph.invoke()를 그대로 노출하면서 streaming까지 지원하려면 보일러플레이트가 많다.

서버 코드 — 핵심은 add_routes 한 줄

# server.py
from fastapi import FastAPI
from langserve import add_routes
from graph import graph

app = FastAPI()
add_routes(app, graph, path="/agent")

# Terminal에서 실행

⚠️ 중요한 참고

LangServe는 현재 유지보수 모드. 수업·로컬 데모용으로 적합.
프로덕션에는 langgraph-cli 기반 LangGraph Platform 사용 권장.

자동 생성 엔드포인트 — 6개

  • /invoke단일 요청 동기 처리. 가장 기본. 요청 1개 → 응답 1개.
  • /batch다중 요청 병렬 처리. 여러 입력을 한 번에 보내면 병렬로 빠르게.
  • /streamSSE 토큰 스트리밍. 생성되는 즉시 토큰 단위로 응답.
  • /stream_log중간 단계 스트리밍. 각 노드의 중간 결과까지 실시간으로.
  • /docsSwagger 자동 문서. 입출력 스키마 자동 생성. 그대로 API 명세.
  • /playground[보조] 브라우저 테스트 UI. 별도 프론트 없이 빠르게 테스트.
+ BONUS

Phoenix Tracing이 켜져 있으면, 이 API 호출도 모두 Phoenix에 자동 기록됨. 프로덕션 트래픽 모니터링이 자연스럽게 된다.

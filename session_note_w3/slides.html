02 · LANGCHAIN03/12
정의 먼저

LangChain — LLM 앱의 LEGO 블록

정의
LLM 애플리케이션 개발을 위한 오픈소스 컴포넌트 프레임워크. 모델·프롬프트·파서·도구를 조합해 LLM 앱을 구성
비유
USB 허브처럼 — 어떤 LLM이든(Claude, GPT, Gemini) 꽂기만 하면 동일한 인터페이스로 동작. 모델을 교체해도 코드 그대로.
ChatModelLLM 추상화. ChatAnthropic · ChatOpenAI 동일 인터페이스
Prompt재사용 가능한 템플릿. from_messages([(system,...),(human,"{q}")])
Parser응답 파싱. StrOutputParser · PydanticOutputParser
LCEL| 연산자로 체인 조립. prompt | model | parser

⚠️ 한계: A→B→C 선형 흐름만 가능. 루프·재시도·조건 분기는 LangGraph 필요.

# LCEL 파이프 — 기본 패턴
from langchain_anthropic import ChatAnthropic
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser

llm = ChatAnthropic(
    model="claude-haiku-4-5-20251001",
    temperature=0
)

prompt = ChatPromptTemplate.from_messages([
    ("system", "친절한 어시스턴트입니다."),
    ("human",  "{question}"),
])

# | 연산자로 체인 조립 (LCEL)
chain = prompt | llm | StrOutputParser()
result = chain.invoke({"question": "안녕!"})

03 · LANGGRAPH04/12
정의 먼저

LangGraph가 필요한 3가지 순간

정의
LLM 에이전트의 상태(State)와 흐름을 방향성 그래프로 표현하는 오케스트레이션 라이브러리. LangChain 위에서 동작.
비유
지하철 노선도처럼 — 각 역(Node)에서 상황(State)에 따라 다음 방향을 결정. 환승(루프)도 가능.
Situation 1
Tool 결과가 틀렸을 때 재시도해야 할 때. 체인은 앞으로만 흐름.
Situation 2
입력에 따라 다른 경로로 분기해야 할 때. "계산 요청"과 "대화"를 구분.
Situation 3
몇 번 반복해야 할지 미리 알 수 없을 때. Tool 루프 필요.
04 · LANGGRAPH05/12
State · Node · Edge — 3가지만 기억하면 됩니다

LangGraph 핵심 구성 요소

01 · STATE

공유 메모리

모든 노드가 공유하는 TypedDict. add_messages Reducer가 메시지를 자동 누적. 덮어쓰지 않음.

class AgentState(TypedDict):
  messages: Annotated[
    list[BaseMessage],
    add_messages  # 자동 누적
  ]
  mode: str
02 · NODE

상태 변환 함수

State를 받아 State 일부를 반환하는 함수. 그래프에 등록되어 엣지에 의해 호출됨.

def chat_node(
    state: AgentState
) -> dict:
  system = pull_prompt(
    "chat_system"
  )
  resp = llm.invoke(
    [SystemMessage(system)]
    + state["messages"]
  )
  return {"messages": [resp]}

05 · TOOLS06/12
정의 먼저

Tool Calling — LLM의 손과 발

정의
LLM이 호출할 수 있는 외부 함수. LLM은 어떤 함수를 어떤 인자로 호출할지만 결정하고, 실제 실행은 코드가 담당.
비유
지휘자(LLM)와 연주자(코드) — 지휘자가 "바이올린 연주해" 신호를 주면 연주자가 실제 소리를 냄. 지휘자는 직접 악기를 연주하지 않음.
ReAct 루프
Thought(어떤 도구?) → Action(tool_calls 생성) → Observation(ToolMessage 수신) → 반복
오늘 구현하는 Tool 3종
  • arithmetic사칙연산 · 거듭제곱 · 나머지 (ast 안전 eval)
  • calculus미분(diff) · 적분(integrate) — sympy 기반
  • matrix행렬식(det) · 역행렬(inv) · 행렬곱(matmul) — numpy
from langchain_core.tools import tool
import sympy as sp

@tool
def calculus(
    expression: str,
    variable: str = "x",
    operation: str = "diff",
) -> str:
    """미분/적분 계산. 'diff'|'integrate'"""
    var = sp.Symbol(variable)
    expr = sp.sympify(expression)
    if operation == "diff":
        return str(sp.diff(expr, var))
    return str(sp.integrate(expr, var))

# LLM에 Tool 바인딩
llm_with_tools = llm.bind_tools(
    [arithmetic, calculus, matrix_calc]
)

Evaluator 3가지 유형

01 · CODE EVALUATOR

수치 정확도

기댓값과 수치 비교. 숫자 ±0.01 오차 허용. 심볼릭 결과는 sympy 동치 확인.

def code_eval(row):
  pred = row["predicted"]
  exp  = row["expected"]
  try:
    if abs(float(pred)
      - float(exp)) < 0.01:
      return {"score": 1}
  except: pass
  diff = sp.simplify(
    sp.sympify(pred) -
    sp.sympify(exp))
  return {"score": diff==0}

08 · LANGSERVE09/12
정의 먼저

LangServe — 에이전트를 API로 서빙

정의
LangChain/LangGraph 에이전트를 FastAPI 기반 REST API로 즉시 배포하는 서빙 라이브러리. add_routes() 한 줄로 6개 엔드포인트 자동 생성.
비유
이름 그대로 Serve — 주방(에이전트)에서 만든 요리를 손님(클라이언트)에게 서빙하는 웨이터. 웨이터 없이는 손님이 직접 주방에 들어와야 함.
# server.py — 핵심은 add_routes 한 줄
from fastapi import FastAPI
from langserve import add_routes
from graph import graph

app = FastAPI()
add_routes(app, graph, path="/agent")

# uvicorn server:app --reload --port 8000
⚠️ 참고

LangServe = 수업·로컬 데모용. 유지보수 모드.
프로덕션 → LangGraph Platform (langgraph-cli)

자동 생성 엔드포인트 — 6개

  • /invoke단일 요청 동기 처리. 요청 1개 → 응답 1개. 가장 기본적인 API.
  • /batch다중 요청 병렬 처리. 여러 입력 한 번에 전송, 병렬 실행.
  • /streamSSE 토큰 스트리밍. 생성 즉시 토큰 단위로 전달.
  • /stream_log중간 단계 스트리밍. 각 노드의 중간 결과까지 실시간.
  • /docsSwagger 자동 문서. 입출력 스키마 자동 생성.
  • /playground[보조] 브라우저 테스트 UI. 별도 프론트 없이 빠른 테스트.
